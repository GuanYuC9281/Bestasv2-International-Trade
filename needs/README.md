# 需求工具（客戶版）

這一頁與 `engineering/` 的內部登入版分開。兩者讀取同一份 `engineering/engine.js` 計算核心，因此 13 個模組的公式與驗證結果保持一致；客戶頁不載入 `engineering/auth.js`，計算在瀏覽器本機進行。推薦結果只有在後端成功保存客戶需求後才會顯示。

目前 `config.js` 的 API 位址留空，送出按鈕會顯示為停用。這是刻意的發佈閘門：**未部署受保護資料庫、AI 與郵件服務前，不收集真實客戶資料，也不假裝已產生 AI 推薦。**

要開放客戶使用：

1. 依 `../needs-api/README.md` 部署 API、MongoDB 與 SMTP，將秘密設在後端環境變數。
2. 將 `config.js` 中的 `BESTA_NEEDS_API_BASE` 改為後端 HTTPS 網址。
3. 在手機與桌面瀏覽器測試假資料提交、資料庫紀錄、通知郵件與 AI 清單，再提供客戶網址。

產品白名單在 `../needs-api/src/catalog.js`。目前只採用官網可核對的設備與方案，不把計算表中的每個模組都宣稱為可販售產品。高溫降溫若沒有官網確認的產品，會轉人工評估。
